OST Weather Station — Pin Connections (Arduino UNO R4 WiFi)
Version: 1.2
Date: 2026-10-09

Diagram: wiring_r4_wifi.svg / wiring_r4_wifi.html (generated by wiring_diagram.py;
keep this file and the script in sync).

This document describes the R4 WiFi all-in-one setup. Multiplexer channels and
digital pins are identical to the classic sender (weather_station.ino). The
nRF24L01 radio is NOT used. Since v1.2 the multiplexer is an Adafruit PCA9548
STEMMA QT board (TCA9548A compatible) that also supplies the I2C sensors with
3.3 V; the former 5 V <-> 3.3 V level shifter for the BME280 is no longer needed.

================================================================================
BOARD
================================================================================

Arduino UNO R4 WiFi
  VIN   6–24 V DC (solar/battery via regulator) OR USB 5 V for bench testing
  5V    PCA9548 V+, rain gauge module, rain drop module, anemometer
  3.3V  Not used (I2C sensors get 3.3 V from the PCA9548 ports)
  GND   Common ground for all components

WiFi: onboard ESP32-S3, 2.4 GHz — no external antenna connector on standard board

================================================================================
I2C BUS (ADAFRUIT PCA9548 STEMMA QT MULTIPLEXER, TCA9548A COMPATIBLE)
================================================================================

Arduino          PCA9548 board (Adafruit product 5626)
-------          -------------
A4 (SDA)    -->  SDA   (header I2C bus = Wire, 5 V logic; NOT the 3.3 V Qwiic port)
A5 (SCL)    -->  SCL
5V          -->  V+    (inputs are level shifted, 10 kOhm pull-ups on board)
GND         -->  GND

Vlogic switch: 3.3 V  -> the eight STEMMA QT ports supply 3.3 V and 3.3 V I2C
                         from the on-board regulator (max 500 mA in total)
Address jumpers A0–A2 open -> 0x70 (same as before; firmware unchanged)

Each sensor is connected to its channel port: 3.3 V, GND, SDA, SCL
(STEMMA QT/Qwiic cable, or a STEMMA QT to pin-header cable for modules
without the connector).

Multiplexer channels (same as classic sender):
  Ch0 (0x01)  PMSA003I particulate matter (I2C 0x12), STEMMA QT cable
  Ch1 (0x02)  BME280 environmental sensor (I2C 0x76), direct (no level shifter)
  Ch2 (0x04)  SEN0636 UV index (I2C 0x23), mode switch on I2C
  Ch3 (0x08)  MLX90614 IR temperature (I2C 0x5A), GY-906 module with 3.3 V regulator
  Ch4 (0x10)  TSL2591 light sensor (I2C 0x29), Waveshare module

================================================================================
DIGITAL / ANALOG PINS
================================================================================

Pin     Function                          Notes
----    --------                          -----
D2      Rain gauge reed module OUT        INPUT, pull-up on the module
D3      Anemometer pulse                  INPUT, interrupt RISING
D4      -> RESET pin of the board         Hourly self-reset (RESET_PIN, RESET_INTERVAL).
                                          Firmware keeps D4 as INPUT and only switches it
                                          to OUTPUT LOW for the reset; never drive it HIGH
                                          (pinMode(OUTPUT) starts LOW -> reset loop)
D5      Rain drop sensor (digital)        INPUT
D6      PMSA003I SET pin                  OUTPUT: LOW=sleep, HIGH=active
A1      Rain drop sensor (analog)         0–1023 (12-bit ADC on R4)

Pins NO LONGER USED (were nRF24L01):
  D8  CSN
  D9  CE
  D10 MOSI
  D11 MISO
  D12 SCK

================================================================================
SENSOR-SPECIFIC NOTES
================================================================================

SUPPLY VOLTAGES (chosen for stable operation)
  The UNO R4 has 5 V logic on A4/A5, so the PCA9548 is powered with 5 V (V+) and
  the main I2C bus keeps 5 V levels. With the Vlogic switch on 3.3 V the board
  supplies all I2C sensors with 3.3 V power and 3.3 V I2C levels from its own
  regulator (500 mA), so neither the R4's 3.3 V output (shared with the WiFi
  module) nor a separate level shifter is needed. All five I2C modules are
  specified for 3.3 V:
    PMSA003I  Adafruit breakout, VIN 3–5 V (generates the fan's 5 V on board)
    BME280    3.3 V sensor
    SEN0636   DFRobot: 3.3–5 V
    MLX90614  GY-906 module with 662K 3.3 V regulator (3 V chip version)
    TSL2591   Waveshare module: 3.3 V / 5 V
  Current from the 3.3 V ports: a few mA for the four small sensors plus roughly
  150–200 mA for the PMSA003I while its fan runs (estimate) -> within 500 mA.
  The downstream channels have no documented pull-ups on the PCA9548 board; the
  sensor modules bring their own. Keep the I2C clock at 100 kHz for the longer
  cables to the sky sensors.

PMSA003I
  Port 0 via STEMMA QT cable (3.3 V, GND, SDA, SCL), SET on D6, RESET not connected
  Sleep between 5-minute measurement cycles (~60–120 mA when active)

SEN0636 UV
  Port 2, hardware switch must be in I2C position

BME280
  Port 1, directly (3.3 V, GND, SDA, SCL); address 0x76

Rain gauge
  Reed module (VCC 5 V, GND, OUT -> D2) with on-board pull-up; debounced in firmware (250 ms)

Rain drop sensor
  Module VCC 5 V, GND, DO -> D5, AO -> A1

Anemometer
  Hall sensor VCC 5 V, GND, SIG -> D3 (interrupt); pulses counted per 500 ms snapshot

================================================================================
POWER BUDGET (APPROXIMATE)
================================================================================

Component              Active        Sleep/idle
---------              ------        ------------
UNO R4 WiFi board      50–80 mA      30–50 mA
WiFi transmit peak     +100–150 mA   0 (disconnected between uploads)
PMSA003I               60–120 mA     <1 mA (SET=LOW)
Other I2C sensors      ~10–20 mA     ~10 mA
(PMSA003I and I2C sensors are fed from the PCA9548 3.3 V regulator, which
 draws its current from the board's 5 V rail)

Recommend: regulator ≥ 500 mA, bulk capacitor on 5 V rail, local 100 nF per IC.

================================================================================
NETWORK
================================================================================

No wired USB data path required in production.

WiFi credentials and API password: secrets.h (copy from secrets.h.example)

Upload target:
  HTTPS POST /weather_station/weather_api/datasets/
  HTTP Basic Auth (dedicated Django user, not admin)

Observatory must provide 2.4 GHz WiFi with internet access for HTTPS + NTP.
